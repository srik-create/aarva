## Recently completed (2026-06-29 → 2026-07-06)

Most recent first.

### 2026-07-06

- **iPhone player pause-on-navigation fixed via htmx partial
  navigation (Thread A from the session plan).** Root cause: every
  `<a>` click was a full page load, tearing down the shared `<audio>`
  element; the 2026-06-25 sessionStorage-restore stopgap papered over
  it but still needed a tap-to-resume on iOS Safari (autoplay
  policy). Real fix: `htmx` 2.0.10 (pinned CDN + SRI, verified against
  htmx.org docs same day) boosts same-domain links/forms on `<body>`,
  scoped via `hx-select`/`hx-target="#main-content"` so only the main
  content area swaps — header, footer, and the persistent audio
  element/mini-bar outside `<main>` are untouched by navigation.
  Player-button wiring (`wireDataPlayers()`) re-runs on
  `htmx:afterSwap` since swapped-in `[data-player]` blocks are fresh
  DOM with no listeners. The episode-build form
  (`/create/build` → 303 redirect → `/build/<job_id>`) is explicitly
  excluded from boosting — htmx's history-URL behavior across a
  boosted-then-redirected request isn't documented, and the status
  page it lands on already does full-page-reload polling every 7s, so
  boosting it bought nothing. Verified end-to-end with a headless
  Playwright pass: audio kept playing across a nav click, mini-bar
  persisted, a play button on the freshly-navigated-to page worked,
  mobile drawer auto-closes on nav-link tap.
- **Listener-created episodes split into a separate DB** (branch
  `listener-db-split`, PR pending). Root cause: `sync_db_to_render.sh`
  atomic-replaces the whole main DB from the laptop's daily snapshot,
  silently wiping listener-built episodes created on Render between
  syncs (2026-07-03: 3 of 4 lost). New `ListenerDatabase`
  (`aarva/listener_db.py`) holds just `editions` / `edition_pieces` /
  `crosscut_embeddings`, with article title/publication/byline
  denormalized onto `edition_pieces` since it has no `articles` table
  — lives at a separate path the sync script never touches. Three
  commits: (1) worker routes on-demand builds there end to end
  (script-gen → TTS → MP3 conversion → R2 upload), `/listener-created`
  + `/crosscut/<id>` read both DBs, `/article/<id>` falls back to the
  listener DB too (discovered mid-build: articles only ever used in a
  listener episode would otherwise 404 there) — also seeds the
  listener DB's edition-id counter at 1,000,000 so it can't collide
  with the main DB's; (2) `/create`'s existing-match search now scores
  against both DBs, tagging each match with its source throughout
  (verified against a deliberate id collision in a synthetic test —
  never merges into a single `{edition_id: ...}` dict, which would
  silently conflate two unrelated episodes); (3) new
  `prompt_classifier.py` classifies the prompt (behind_the_news /
  future_gazing / evergreen) via the existing Gemini `LLMClient`, and
  a 6-day age gate (`search.max_age_days_news` in pipeline.yaml,
  mirroring Stage 7's `lens_card_behind`/`lens_card_future`
  `max_age_days=6` — verified in `stage_7_assemble.py` rather than
  taken on faith) applies only to news-shaped prompts. Verification
  (real /create build + sync-script check) still to run before PR
  sign-off.

### 2026-07-04

- **Independence-Day bonus published end-to-end** via `aarva.search`
  → `aarva.publish_articles` → `daily --stage 10` → `publish.sh` →

### 2026-07-02

- **Worker resilience** (PR #49) — three-commit landing that ended
  the Render OOM + health-check-timeout loop on `/create`:
  - `propose_candidates` moved to threadpool so /health polls
    aren't starved during the 10-30s LLM+embedding call.
  - TTS streams PCM chunks directly to the wav file instead of
    accumulating ~90 MB of PCM in memory; peak footprint drops from
    ~200 MB to ~50 MB per build.
  - Worker checkpoints `edition_id` back into job payload after
    step 2, so a Render restart mid-build resumes at TTS instead of
    duplicating the LLM proposal + edition creation.
- **Docker ffmpeg** (PR #47). Container was missing ffmpeg; build
  worker crashed at `audio_converter.convert_all_for_publish`.
  Dockerfile now installs it. Uncovered because Phase-2's on-Render
  audio-conversion path had never actually completed a build
  successfully — everything before this was OOM'ing further up.
- **Embedding batch cap** (PR #45, then #46 with correct value).
  Stage 1.5's straggler backfill hit Vertex AI's per-call limit;
  first fix set batch size to 2000 from an ambiguous error message,
  actual model-specific cap is 250. Final value 200 with headroom.
  Added AGENTS.md rule 6 "partial-signal trap" clause.

## Decisions made (for future reference)

Every material trade-off gets one row here. This is the "why" doc —
for the raw historical detail see `docs/project_brief.md`'s
decision log.

| Decision | Rationale | Reversibility |
|---|---|---|
| Render.com for web-app hosting | Python+SQLite-native; ~$7/mo; git-push deploy. | Dockerfile is canonical; switching providers is config-only. |
| `aarva.app` on Cloudflare DNS | User-registered; Cloudflare also fronts R2 audio. | Standard DNS — movable. |
| Email-on-request only (no full auth) v1 | Public catalog; low-friction crosscut requests. | Adding magic-link auth later is purely additive. |
| Gemini for all non-coding LLM work | Standing preference; Claude reserved for coding. | Config-only via `llm.provider` in pipeline.yaml. |
| Gemini auth: ADC/Vertex, NOT AI Studio api_key | (2026-06-13) gibran.ai data-residency policy + AI Studio spending caps. Re-confirmed 2026-07-01 after a brief same-day flip and revert. | YAML edit + operator config. |
| Vertex AI project: `gen-lang-client-0889802137`, location `global` (LLM) / `us-central1` (embeddings) | Only location serving Gemini 3 Flash Preview for this project (verified via probe). Embeddings uses us-central1 (global not valid for embeds). | YAML edit. |
| Embeddings: `gemini-embedding-001` at 768-dim Matryoshka | Same shape as prior BGE storage; keeps DB blob layout intact. | Re-embed script exists for any future model change. |
| SQLite as primary DB | Single-file, no ops. | Migrate to Postgres ~2 days of work if scale demands. |
| Daily pipeline runs on operator's laptop | Explicit control; the pipeline isn't time-sensitive enough for automation to justify. | `scripts/app.aarva.daily.plist` exists as a starting point if scheduled runs are ever wanted. |
| Listener episodes: split-DB (shipped 2026-07-06) | Sync overwrites Render DB, wiping listener episodes built between syncs. Split file on Render's persistent disk that sync never touches. Denormalize article title/pub/byline onto edition_pieces at build time so no cross-DB joins. Listener DB's edition-id AUTOINCREMENT seeded to 1,000,000 to avoid colliding with the main DB's ids (both start at 1 independently). | Split file is on disk; can be merged back into main DB if we ever want. |
| Prompt classification via Gemini for search age gate (shipped 2026-07-06) | News-y prompts shouldn't match old listener episodes; evergreen prompts should. One small Gemini call at /create time, reusing the existing LLMClient interface. Falls back to 'evergreen' (no filter) on any classifier failure — degrades to "search everything" rather than hiding valid matches. | Config gate + one file (`prompt_classifier.py`) to remove. |
| htmx (2.0.10, pinned CDN) for partial navigation, over a hand-rolled fetch+DOM-swap (2026-07-06) | User picked the library option: battle-tested history/back-button/script-re-execution handling vs. custom code for the same edge cases. One `<script>` tag, same CDN pattern already used for Tailwind. | Swap-out is a base.html-only change; no server-side coupling beyond serving full pages as already done. |

## How to use this doc

- **AI agents**: read this at the start of any session. Cross-reference
  against the user's request to surface deferred items if relevant
  (e.g., "before we add search, we still need crosscut embeddings —
  is that still the order?").
- **Updating**: per AGENTS.md rule 17a (Roadmap freshness) — any
  commit that lands a deferred item, finishes a phase, defers
  something new, changes a Phase Plan status column, or makes a
  decision worth logging MUST update this file in the same PR.
  Sign-off protocol (rule 20a) requires verifying this doc has been
  updated before the user reviews. Goal: the doc never drifts from
  reality by more than one commit.
- **Format**: prose + tables. No emojis (per AGENTS.md rule 14).
