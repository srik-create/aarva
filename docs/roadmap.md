## Deferred — to return to (in priority order)

1. **Crosscut embeddings for vector-space discoverability.** Currently
   each article gets one BGE embedding; crosscuts are only discoverable
   via JOINs through their underlying articles. After Phase 1 ships,
   compute an embedding per crosscut episode (concat / mean of the
   two underlying articles, or embed a "pairing summary" text), store
   in a new `crosscut_embeddings` table, update search to query both.
   **Trigger: before Phase 2 (search) begins.**

2. **Hook prompt rewrite (Stage 8a).** Current hooks are conversational
   but don't always pull out the most critical "why" for the listener.
   User wants a one-sentence hook that draws out the specific reason
   the article matters — the angle that makes it worth listening to.
   **Trigger: anytime; small focused prompts.yaml change.**

   LUFS, all 17-June-onwards MP3s re-normalized. User to listen and
   confirm chunk-to-chunk volume variance has dropped meaningfully.
   **Trigger: next time the user listens to a recent episode.**

5. **Verify YouTube re-ingests after audio.aarva.app switch.**
   2026-06-26 switched `tts.r2.public_url_base` from `pub-xxx.r2.dev`

## Decisions made (for future reference)

| Decision | Rationale | Reversibility |
|---|---|---|
| Render.com for web-app hosting | Python+SQLite-native; ~$7/month; git-push deploy. Alternatives (Fly.io, DO) are similar. | Dockerfile is canonical; switching providers is config-only. |
| `aarva.app` domain via Cloudflare DNS | User registered; Cloudflare also serves R2 audio + (future) CDN in front of Render app. | Standard DNS — movable. |
| Email-on-request only (no full auth) for v1 | Public catalog + low-friction crosscut requests. Auth deferred. | Adding magic-link auth later is purely additive. |
| Crosscut UX: automatic suggestion | Single LLM call per search; better product feel than explicit button. | Behind a feature flag if needed. |
| NL search primary, structured filters secondary | One-input UI is cleanest. Advanced toggle deferred. | Filter UI added later without backend change (NL parser already produces structured filters). |

## How to use this doc

- **AI agents**: read this at the start of any session. Cross-reference
  against the user's request to surface deferred items if relevant
  (e.g., "before we add search, we still need crosscut embeddings —
  is that still the order?").
- **Updating**: any commit that lands a deferred item, finishes a phase,
  or defers something new should update this file in the same PR. The
  goal is the doc never drifts from reality by more than one commit.
- **Format**: prose + tables. No emojis (per AGENTS.md rule 14).
